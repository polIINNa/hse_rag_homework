# Описание реализации RAG

## Архитектура

Реализация находится в [`eval/rag_example.py`](eval/rag_example.py), класс `RAG`.

### 1. Извлечение текста из PDF (с учётом таблиц)
- Источник метаданных: `data/documents.jsonl` (`doc_id`, `path`, организация, число страниц).
- PDF открываются из `data/reports/<path>` с помощью **PyMuPDF (`pymupdf`/`fitz`)**.
- Текст извлекается **постранично** с сохранением `doc_id`, номера страницы `page` (1-based) и метаданных.
- Дополнительно используется `page.find_tables()` для извлечения табличных данных; строки таблиц добавляются к тексту страницы в виде структурированных строк (`колонка | колонка | ...`).
- Текст нормализуется, пустые страницы не индексируются.

**Зачем:** метрики контекста считаются по `(doc_id, page)`, а табличное представление помогает находить и передавать в ответ числовые показатели из отчётности.

### 2. Чанкинг и индекс с эмбеддингами
- Каждая страница разбивается на **перекрывающиеся чанки** (~1200 символов, overlap ~200).
- Для каждого чанка считается эмбеддинг локальной моделью **`sentence-transformers`** (по умолчанию `intfloat/multilingual-e5-small`, `EMB_MODEL`).
- Для e5 используются префиксы `passage:` (чанки) и `query:` (запрос). Эмбеддинги нормализуются, сходство — косинусное.
- Кэш: `eval/cache/chunks_v2.jsonl` и `eval/cache/embeddings_v2.npy`.
- Сборка индекса: `python -m eval.build_index --batch-size 32` (прогресс, возобновление). Если чанки/эмбеддинги уже есть в кэше, они переиспользуются; для применения улучшенного извлечения (таблицы) нужно удалить старый `chunks_v2`/`embeddings_v2` и пересобрать индекс.

**Зачем:** чанки точнее соответствуют локальным фрагментам/таблицам, чем целая страница.

### 3. Гибридный поиск (retrieval)
- Базовый скор: косинусная близость эмбеддингов запроса и чанков.
- **Метаданные:** из вопроса извлекаются банк/организация, год(ы) и период (`6m`/`annual`); к скору применяется буст/штраф по совпадению с `doc_id` (`<org>_<year>_<period>`).
- **Лексический сигнал:** небольшой дополнительный буст за совпадение значимых терминов вопроса с текстом чанка (помогает при точных формулировках/терминах).
- Отбираются top кандидаты-чанки, агрегируются до **лучшего скора на страницу**, затем выбираются top-N страниц (`RAG_TOP_K`, по умолчанию **8**).
- Результат группируется по `doc_id`: `[{"doc_id": "...", "pages": [1, 2]}]`.

### 4. Agentic RAG (дополнительный поиск по решению агента)
Метод `_agentic_retrieve` реализует агентное поведение:
1. Выполняет **первичный поиск**.
2. **Анализирует вопрос и покрытие** результатов: какие банки/годы/периоды упомянуты, является ли вопрос сравнительным/многоаспектным.
3. **Принимает решение** о необходимости дополнительного поиска: если важная сущность (банк или год в сравнительном/многолетнем вопросе) не представлена в выдаче, запускает **целевые дополнительные поиски** с усиленными фильтрами по недостающей сущности.
4. **Объединяет** результаты нескольких поисков (максимальный скор на страницу, контроль уникальности, ограничение числа доп. поисков) и возвращает итоговый набор страниц.

**Зачем:** для сравнений, динамики и вопросов по нескольким отчётам одного поиска часто недостаточно; агент сам достраивает покрытие контекста.

### 5. Генерация ответа
- В промпт передаётся **полный текст найденных страниц** (все чанки страницы) с указанием `doc_id`, страницы и скора.
- Если задан `GEN_API_KEY` или `LLM_API_KEY`, выполняется запрос к LLM API (по умолчанию `https://claude.gigaparsers.ru/v1/messages`, `GEN_MODEL`=`deepseek-flash`) с инструкцией отвечать **только по контексту**, точно сохранять числа/валюты/единицы/масштаб/периоды и отвечать на все части составного/сравнительного вопроса.
- В запросе отключён reasoning (`thinking: disabled`), чтобы `max_tokens` расходовался на ответ.
- При пустом ответе — повторная попытка, затем извлекающий fallback; при отсутствии ключа/ошибке API — fallback.

### 6. LangSmith: трейсы и метрики (доп. балл)
- В `eval/rag_example.py` ключевые шаги (`rag`, агентный retrieval, поиск, генерация) обёрнуты в `@traceable` (безопасный no-op, если LangSmith недоступен/выключен).
- В `eval/run_eval_resumable.py` каждый вопрос оценивается в traceable-контексте и в LangSmith отправляются feedback-метрики: `context_recall`, `context_precision`, `answer_correctness`, `time`.
- Включение: переменные окружения `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`, (опц.) `LANGSMITH_PROJECT`, `LANGSMITH_ENDPOINT`. Запуск eval — обычный; эксперимент с трассами и метриками становится доступен в LangSmith.

### 7. Воспроизводимость времени ответа
- Модель эмбеддингов загружается и прогревается в `RAG.__init__` до первого вопроса, чтобы её загрузка не попадала в `time` первого запроса.
- Генерация: `temperature=0`, reasoning отключён.

## Используемые библиотеки
- `pymupdf` — извлечение текста и таблиц из PDF
- `sentence-transformers`, `torch`, `numpy` — эмбеддинги и векторный поиск
- `requests` — HTTP-запросы к LLM API
- `openpyxl` — формирование Excel-отчёта (eval)
- `langsmith` — трассировка RAG и логирование метрик (опционально)

## Параметры (переменные окружения)
| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `LLM_API_KEY` | Ключ для LLM-судьи (`eval/eval_functions.py`, `answer_correctness`). Также может использоваться для генерации, если `GEN_API_KEY` не задан. | — |
| `GEN_API_KEY` | Ключ для генерации ответа в RAG. | = `LLM_API_KEY` |
| `GEN_BASE_URL` | Endpoint генерации (Anthropic Messages-совместимый). | `https://claude.gigaparsers.ru/v1/messages` |
| `GEN_MODEL` | Модель генерации. | `deepseek-flash` |
| `EMB_MODEL` | Локальная модель sentence-transformers. | `intfloat/multilingual-e5-small` |
| `LANGSMITH_TRACING` | Включить трассировку в LangSmith (`true`). | выключено |
| `LANGSMITH_API_KEY` | Ключ LangSmith. | — |

## Известные ограничения
- Три PDF — сканы без текстового слоя: `alfa_2024_annual` (`alfa/2024/annual.pdf`), `gpb_2023_annual` (`gpb/2023/annual.pdf`), `gpb_2025_annual` (`gpb/2025/annual.pdf`). Для них текст не извлекается и страницы не индексируются. В `data/test.jsonl` 18 вопросов ссылаются на эти документы в `gold_context`. Улучшение требует OCR и переиндексации.
- Структура сложных таблиц восстанавливается эвристически; для некоторых отчётов возможны потери форматирования. Для максимального эффекта от табличного извлечения нужен пересчёт индекса.
